# 方向策略

方向用于把设计选择权交给用户。凡是产生新视觉设计，都先交付三套主题完全不同的完整方向。

## 选择数量

| 情况 | 输出 |
|---|---|
| 新设计、重新设计、视觉改版、跨平台设计 | 3 个完整方向 |
| 明确单页、成熟品牌、已有流程或现成实现 | 仍为 3 个完整方向 |
| 用户已选定方向后的迭代 | 只深化所选方向 |
| 审计或不产生新视觉的机械修改 | 不走方向门 |

参考实现只用于确认功能与契约，不构成减少方向或沿用页面结构的理由。多平台任务先定一份共享功能与状态模型，再为每个平台制作三套平台原生方向；平台版本本身不算不同方向。新设计不能以时间、成本、品牌成熟度或用户给了参考实现为由减少到一套。

## 方向必须真正不同

三个方向必须各自从空白便笺开始，并在下列四项上形成不同答案：

- 产品解释：它把产品理解成什么。
- 信息结构：用户怎样阅读与推进。
- 操控模型：点击、直接操控、编辑或导航如何组织。
- 视觉材料：图像、排印、表面、空间和数据的角色。

核心功能、接口契约、起始数据和业务结果保持一致。不得把不同功能页、Light/Dark、不同设备尺寸或删减功能充当三个方向。只换色、圆角、字体、插图或卡片排列不构成新方向；不得完成 A 后复制其 DOM/组件树再改出 B/C。

## 方向便笺

制作前为每个方向写 6 行以内：

```text
产品解释：
核心对象：
主要动作：
内容结构：
视觉材料：
动态论点：
```

## 每个方向的最低交付

- 一份独立可运行、可操作的原型，承接同一核心路径。
- 一张从该原型真实渲染捕获的完整预览图。
- 一句能说清产品解释差异的定位，以及信息结构、操控模型和视觉材料说明。
- 保存、取消、返回及本次范围内的关键结果可验证。

三套同时展示后停止，不替用户预选，也不先实现其中一套。

生活化动作不是必选项。所有方向都可做机会扫描，但通常最多一个方向采用强物理隐喻；产品本身是游戏、模拟或创作工具时除外。
