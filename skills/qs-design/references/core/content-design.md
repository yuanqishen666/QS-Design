# 内容设计：必要、真实、不重复

界面文字服务识别、决策、操作和恢复，不负责填满留白。页面包含用户可见文字时读取本文件；各平台只补充本地化、组件和辅助技术差异。

## 来源优先级

1. 用户明确提供的文案。
2. 现有产品、代码、产品文档和已确认术语。
3. 真实业务数据或贴近领域的明确演示数据。
4. 为理解操作所必需的最小补充。

不要自行发明卖点、评价、指标、优惠、品牌承诺或尚未实现的能力。内容不足时保持简洁，在原型说明中标记待确认，不用口号掩盖缺口。

## 文案准入

每段文字至少完成一项任务：

- 识别当前对象、位置或任务；
- 说明关键状态、规则、限制或后果；
- 指示下一步动作；
- 防止错误或帮助恢复；
- 提供当前决策需要的数据。

如果文字只是在模拟人与用户对话、填补空白、重复界面或制造“高级感”，默认删除。未经用户或品牌依据，不添加装饰性英文眉题、励志口号、模块导语、emoji、感叹号和拟人化寒暄。

## 单一信息归属

| 位置 | 主要职责 |
|---|---|
| 页面标题 | 当前对象或主要任务 |
| 模块标题 | 新的内容分组 |
| 辅助说明 | 新增的原因、规则、影响或限制 |
| 列表项 | 具体对象、选项或数据 |
| 按钮 | 即将执行的动作 |
| 状态标题 | 发生了什么 |
| 状态正文 | 下一步或恢复方式 |

正文不得只是标题的同义改写。列表标题说清共有语义后，从子项中去掉重复前缀。上下文已经明确对象时，按钮不重复对象名；上下文不足时保留清楚的动词加对象。

## 去重检查

交付原型前检查当前页面和相邻步骤：

- 页面标题与首个模块标题是否表达同一件事；
- 标题、副标题和卡片描述是否只是换一种说法；
- 列表项是否重复列表标题而没有具体对象或数据；
- 状态正文是否改写状态标题；
- 多个选项是否共享可提取到分组标题的前缀；
- 前后页面是否连续重复同一说明。

使用删除测试：删除其中一段后，如果没有损失新的事实、规则、状态或动作，就删除层级较低的一段。`scripts/content-lint.mjs` 只提供重复线索，最终以实际语义和上下文判断。

## 允许重复的情况

重复只有在安全、确认、定位或可访问性需要时保留，例如不可逆操作、金额与收件人确认、跨页上下文、无障碍名称或间隔很久后需要重申的关键信息。原型 HTML 可用 `data-content-repeat-ok="safety|a11y|cross-screen-context"` 标记机械检查的合理例外；标记不能替代真实理由。

## 短、具体、一致

- 标题说当前对象或任务；按钮使用清楚动作；状态说明结果。
- 空状态先说发生了什么，再给可行下一步；错误说明问题与恢复方式。
- 同一对象和动作始终用同一个词，不在“完成、确认、保存、应用”之间随意切换。
- 删除“开启、探索、解锁、沉浸式、焕新、赋能”等空泛前缀，以及“不只是……更是……”等 AI 式对仗。
- 使用真实长度、真实数字和贴合领域的示例，不用 Lorem ipsum、`Sample Title` 或整齐但失真的等长文案。

产品可以有性格，但高频任务更直接，完成时才适度温暖，风险和错误不卖萌。儿童、游戏或明确角色型产品可以更活泼，动作含义仍须准确。
