# 内容设计：结构先解释，文字只承担不可替代语义

界面文字服务识别、决策、操作和恢复，不负责填满留白，也不替布局、层级和控件补作业。页面包含用户可见文字时读取本文件；各平台只补充本地化、组件、输入方式和辅助技术差异。

目标不是制造一种“少字的 QS 风格”，而是让每个可见元素承担当前业务职责。金融、医疗、法律、隐私、授权和不可逆操作可以比轻量工具包含更多文字；多少不是标准，是否不可替代才是标准。

## 来源优先级

1. 用户明确提供的文案。
2. 现有产品、代码、产品文档和已确认术语。
3. 真实业务数据或贴近领域的明确演示数据。
4. 为理解操作所必需的最小补充。

不要自行发明卖点、评价、指标、优惠、品牌承诺或尚未实现的能力。内容不足时保持简洁，在原型说明中标记待确认，不用口号掩盖缺口。

## 结构替代测试

生成标题以外的说明、提示或描述前，依次回答：

1. 这段文字新增了什么事实、规则、状态、动作或决策信息？
2. 能否通过分组、顺序、对齐、空间、尺寸、控件形态、真实数据或状态反馈表达？
3. 删除后，用户是否仍能识别当前对象、主操作和操作结果？
4. 隐藏后，是否可能造成错误、损失、隐私问题或不可逆后果？
5. 是所有人、多数人、少数人需要，还是只在首次、错误或按需时需要？

第 1 项没有答案时删除。第 2 项可行时先改结构。第 4 项为“是”时，在决策点常驻显示。只有少数用户按需需要的简短非关键信息，才有资格使用 tooltip。

布局只能表达关系和重要性，不能可靠表达“会自动扣费”“数据将提供给第三方”“删除后不可恢复”等业务语义。这些内容不得以画面干净为由隐藏。

## 文案准入

每段文字至少完成一项任务：

- 识别当前对象、位置或任务；
- 说明关键状态、规则、限制或后果；
- 指示下一步动作；
- 防止错误或帮助恢复；
- 提供当前决策需要的数据。

如果文字只是在模拟人与用户对话、填补空白、重复界面或制造“高级感”，默认删除。未经用户、品牌或业务依据，不添加装饰性英文眉题、励志口号、模块导语、emoji、感叹号和拟人化寒暄。

默认禁止把“页面标题 + slogan + 描述”“模块标题 + 每区说明”“卡片名称 + 同义描述”当成固定组件骨架。先让内容关系、数据和主操作形成层级，再判断是否仍缺少不可替代语义。

## 信息显隐梯度

按以下顺序选择表达方式，不从 tooltip 反向收纳多余文案：

| 顺序 | 表达方式 | 适用条件 |
|---|---|---|
| 0 | 删除 | 不增加事实、规则、状态、动作或决策信息 |
| 1 | 结构表达 | 分组、层级、空间、数据关系、控件或状态足以表达 |
| 2 | 常驻标签或状态 | 对象、主操作、关键状态、金额、权限、限制与后果等多数用户必须知道的信息 |
| 3 | 就地短提示 | 多数用户在当前操作时需要，且结构无法可靠表达；通常一个短句 |
| 4 | Details / popover | 少数用户需要的较长解释、示例、定义或可交互内容 |
| 5 | Tooltip | 与单个触发对象强相关的简短、非关键、按需信息 |
| 6 | 情境教学 | 新颖且无法自解释的功能；只在首次或刚变得相关时出现 |

辅助性内容必须在[内容显隐契约](../../docs/content-contract.md)中记录 `purpose / criticality / audience / timing / delivery / irreducible_fact / structure_attempt`。它属于业务模型的 `content_graph`，不是独立的视觉风格层。标题、普通标签、按钮和原始业务数据无需为了形式完整重复填写这些字段。

## Tooltip 不是默认答案

Tooltip 只用于：

- 陌生图标按钮的简短名称；
- 缩写或术语的短定义；
- 无法避免的截断内容全文；
- 非关键快捷键信息。

Tooltip 禁止承载：

- 完成任务所需的规则、输入格式和验证条件；
- 金额、收费、续费、权限、数据用途和操作后果；
- 错误原因、恢复步骤或不可逆操作确认；
- 链接、按钮、表单或其他可聚焦内容；
- 只有 hover、长按或精细指针才能发现的能力；
- 已经由可见标签表达的重复内容。

静态实现至少具有明确触发器、可访问名称和 `aria-describedby` 等语义关系。运行时必须验证键盘焦点、指针悬停、触控替代、Escape 关闭、内容可悬停与持续显示。Tooltip 不接收焦点；需要交互时使用 Details、popover 或 dialog/toggletip。不要以原生 `title` 属性作为唯一实现，也不要绑定 disabled 元素。

Info 图标本身会增加视觉噪音和发现成本。只有存在明确解释对象、内容通过按需披露仍安全、且各输入方式都有入口时才添加；不能因为“想让页面少字”而在每个区块旁批量放置。

## 单一信息归属

| 位置 | 主要职责 |
|---|---|
| 页面标题 | 当前对象或主要任务 |
| 模块标题 | 新的内容分组 |
| 辅助说明 | 新增的原因、规则、影响或限制 |
| 列表项 | 具体对象、选项或数据 |
| 按钮 | 即将执行的动作 |
| 状态标题 | 发生了什么 |
| 状态正文 | 下一步或恢复方式 |

正文不得只是标题的同义改写。列表标题说清共有语义后，从子项中去掉重复前缀。上下文已经明确对象时，按钮不重复对象名；上下文不足时保留清楚的动词加对象。

## 必须保留的可见文字

- 表单的可见标签与多数用户需要的格式要求；
- 金额、费用、续费、交易对象、权限、隐私和授权后果；
- 不可逆操作的对象、影响和确认信息；
- 错误原因、当前状态和可执行恢复方式；
- 不熟悉且不存在通用视觉隐喻的业务概念；
- 不能只靠颜色、图标、位置或动效表达的状态。

无障碍名称不能自动替代可见标签。Placeholder 不能充当标签。熟悉的图标按钮可以使用可访问名称和短 tooltip，但当文字比图标更清楚时直接使用文字。

## 去重检查

交付原型前检查当前页面和相邻步骤：

- 页面标题与首个模块标题是否表达同一件事；
- 标题、副标题和卡片描述是否只是换一种说法；
- 是否机械地给每个同级模块都添加一段说明；
- 列表项是否重复列表标题而没有具体对象或数据；
- 状态正文是否改写状态标题；
- 多个选项是否共享可提取到分组标题的前缀；
- 前后页面是否连续重复同一说明；
- info 图标是否只是隐藏本可删除的文字。

使用删除测试：删除其中一段后，如果没有损失新的事实、规则、状态或动作，就删除层级较低的一段。`scripts/content-lint.mjs` 提供重复、显隐契约和 tooltip 结构线索，最终仍以实际业务和运行证据判断。

## 两项交付验证

### 无辅助文案任务测试

临时隐藏 `supporting / optional` 内容，检查用户是否仍能识别对象、找到主操作、理解核心关系、判断结果并从错误中恢复。失败时先修复结构；只有确有不可替代事实时才恢复文字。

### 关键事实可见性测试

逐项检查金额、权限、风险、约束、不可逆后果和输入格式：是否在决策点出现，是否无需 hover、长按或打开隐藏层，是否尽可能在错误前提供，是否不只由颜色或图标表达。

自动检查不得把“字少”或固定字数当成质量指标。验证分别报告解释依赖、关键事实可见性、披露输入等价性和误删风险。

## 允许重复的情况

重复只有在安全、确认、定位或可访问性需要时保留，例如不可逆操作、金额与收件人确认、跨页上下文、无障碍名称或间隔很久后需要重申的关键信息。原型 HTML 可用 `data-content-repeat-ok="safety|a11y|cross-screen-context"` 标记机械检查的合理例外；标记不能替代真实理由。

## 短、具体、一致

- 标题说当前对象或任务；按钮使用清楚动作；状态说明结果。
- 空状态先说发生了什么，再给可行下一步；错误说明问题与恢复方式。
- 同一对象和动作始终用同一个词，不在“完成、确认、保存、应用”之间随意切换。
- 删除“开启、探索、解锁、沉浸式、焕新、赋能”等空泛前缀，以及“不只是……更是……”等 AI 式对仗。
- 使用真实长度、真实数字和贴合领域的示例，不用 Lorem ipsum、`Sample Title` 或整齐但失真的等长文案。

产品可以有性格，但高频任务更直接，完成时才适度温暖，风险和错误不卖萌。儿童、游戏或明确角色型产品可以更活泼，动作含义仍须准确。
