# 产品事实、注意力与术语合同

这三份合同在视觉方向之前建立，作用是防止模型用“合理猜测”填补产品空白。它们属于当前 Task Capsule，不是项目或 profile 的长期审美记忆。

## Product Truth

Product Truth 可以来自当前对话、已有产品，或二者共同提供。至少记录：

- 首要用户任务及优先级；
- 关键旅程、入口、步骤和结果；
- 已存在、已确认或本任务要求的页面、状态与可见操作；
- 可见控件 allowlist；
- 用户明确禁止虚构的功能、人物、场景、数据和示例；
- 会改变产品本质但尚未确认的 unknown；
- 代表任务及其频率、风险或学习价值依据；
- fixture 是真实来源、明确演示，还是不应出现。

没有项目文件夹时，用户当前对话就是事实源；不得因为缺少仓库而降低来源要求。已有项目时，源码和运行页面可提供事实，但用户当前修正优先。未列入 allowlist 的操作不能进入正式候选；必要但未知的操作应先保留为 unknown。

## Attention Contract

Attention Contract 不指定固定排版或视觉风格，只冻结第一视口中的业务注意力：

1. 用户第一眼需要完成的判断；
2. 唯一 rank-1 主操作；
3. 次要入口和三级上下文的顺序；
4. 必须安静退后的对象；
5. 五秒、模糊/眯眼、灰度、焦点顺序和文字缩放证据。

主操作“存在”不等于主操作“取得视觉支配权”。检查必须针对最终渲染产物；没有运行或人工证据时保持 `unknown`。

## Terminology Contract

关键概念记录用户实际含义、候选标签、普通用户可能产生的另一种理解、禁止同义词、来源和解决方式。先用改名或结构消除歧义，再考虑可见定义；不要用常驻辅助文案补救一个本身会误导的标签。

每个有风险的术语执行 label-only prediction：只看标签时，用户能否预测下一屏或下一状态。`聊天背景` 这类会自然指向另一概念的词，应在生成界面之前被拦截。

## 重置

- `soft-reset` 默认保留 Product Truth，因为它是业务事实；Attention、Terminology、Prototype 和 Reference Synthesis 必须逐项再授权。
- `hard-reset` 不自动保留任何设计合同，只有用户当前逐项确认的合同才能进入新上下文。
- 合同只影响当前任务；没有用户明确授权，不得提升为 project 或 profile 规则。
