# 交互基因

交互案例必须能回答“用户为什么动、状态怎样变、被打断后怎样恢复”，不能只记录缓动和时长。

## 记录维度

| 维度 | 问题 |
|---|---|
| 目的 | 解释、连续性、反馈、操控、等待、确认、恢复或愉悦？ |
| 输入 | 点击、按压、拖动、甩动、捏合、旋转、滚动、键盘、语音、传感器？ |
| 连续映射 | 位置、速度、角度、压力、时间如何映射到视觉与状态？ |
| 约束与物理 | 范围、弹簧、衰减、摩擦、碰撞、重力、阻力、形变？ |
| 阈值 | 预览、可提交、危险、不可逆、完成在哪发生？ |
| 状态 | 静止、预备、操控、提交、取消、打断、回弹、稳定、残留？ |
| 反馈 | 视觉、文字、声音、触感和系统状态怎样分工？ |
| 可逆性 | 怎样取消、撤销、反向、重复进入？ |
| 降级 | 减弱动态、键盘、读屏、低性能和平台不支持时怎样完成？ |

## 频率门

- 高频核心动作：即时、安静、短或不动画；反馈优先于表演。
- 中频导航/编辑：用连续性和状态变化减少迷失。
- 低频完成/里程碑：可以更有性格，但不延迟下一任务。
- 首次教学：只在确有学习成本时使用，必须可跳过且不重复打扰。

## 实现不变量

- 新输入能接管当前运动；取消不会误提交。
- 状态结果不只靠运动表达，静止帧与辅助技术仍能理解。
- 速度在手势、释放与后续运动之间尽量连续。
- 触感/声音绑定因果节点，不为普通点击遍地播放。
- 复杂材质层不替代 DOM/原生语义层。
