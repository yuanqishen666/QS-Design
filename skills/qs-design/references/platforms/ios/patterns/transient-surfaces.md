# 临时界面：完成一个短任务，再回到上下文

Sheet、Popover、Menu 和 Dialog 出现时读取。先确定任务、输入与退出含义，再选择容器；不要求每种浮层都有保存、拖动和未保存提示。

## 容器由任务决定

- Sheet 适合与当前内容相连的选择、短编辑和补充信息。
- 非模态面板适合同时操作面板与后方内容，需明确哪些区域仍可交互。
- Popover / Menu 适合锚定触发源的少量信息与动作。
- Dialog / Alert 适合需要中断关注的重要选择；长表单使用足够空间的编辑面。

SwiftUI 优先系统容器。HTML 简单模态可用原生 `dialog`，菜单或锚点面板按实际需要选择浏览器能力或合适组件，不为模拟全部原生细节增加复杂拖拽。

## 编辑草稿与退出

打开编辑器时从已提交内容建立草稿。保存提交并更新父界面；取消保留原值；重新打开读取上次保存值。显式取消、关闭、允许的遮罩点击、Escape 与已实现的拖动关闭应调用同一种取消语义。

无修改时直接退出。轻量、易重做的编辑取消时可丢弃草稿；昂贵编辑按实际需求提供继续、放弃或保存草稿。只有需要保护真实内容时才增加退出确认，不给每个普通选择弹确认框。即时生效的设置没有保存草稿语义，应按实际产品行为表达。

## 输入、滚动和拖动各有归属

默认让正文自然滚动、表单归输入控件处理、可见把手负责拖动。简单弹层无需可拖时不画把手，保留明确关闭或取消入口即可。

确需自定义拖动时：

- 只在拖动区域追踪 Pointer Events，辨认方向意图后捕获活动 pointer。
- 位置连续跟手；放手后按意图提交或回弹，取消与失去捕获有确定落点。
- 不抢 `input`、`textarea`、`select` 或 `contenteditable` 的聚焦、选择与键盘行为。
- 保留正文自然滚动；需要整面拖动时才处理滚动边界仲裁，不照搬历史超时与键盘补偿参数。
- 防止拖动结束后误触点击，让新的输入可接管动画。

先使用浏览器和系统的键盘布局行为；必要时局部处理，确保关键动作可达，不默认接管整页高度或禁止滚动。

## 视觉线索与实际行为一致

把手表示可拖，detent 表示可停靠到相应高度，按钮名称应对应结果。只展示本次实际实现的交互线索。模态遮罩阻止后方按钮被误触；轻量 HTML 弹层可将遮罩点击设为取消，若任务不允许，则保留清楚的其他退出方式。

遮罩关闭和允许操作背景是不同能力。模态关闭时恢复触发入口的焦点，入口已不存在时回到合理结果位置；使用键盘与辅助功能时也能进入、完成和退出。

## 平台实现

SwiftUI 使用 `.sheet`、`presentationDetents`、`presentationDragIndicator` 等实际支持的系统能力。需要保护编辑内容时再按状态控制交互关闭；`presentationBackgroundInteraction` 决定后方内容是否可操作，不等于点遮罩关闭。

HTML 原生 `dialog` 可承担模态与焦点范围，结合 `cancel` / `close`、明确按钮和按需遮罩策略管理草稿。自定义拖动属于额外实现；不暗示网页已经拥有原生 Sheet 的全部手势、触觉与键盘行为。

在成品中走通当前实际路径：进入、操作、完成或取消、重新打开与返回。无编辑的菜单不强加保存流程，无拖动的弹层不强加 detent。实现辅助见 [交互语法](../interaction-grammar.md) 与 [原型交付](../prototype-output.md)。
