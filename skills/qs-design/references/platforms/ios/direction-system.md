# 方向系统：同任务下的独立产品解释

用户需要比较方案时读取。已有品牌、明确参考或局部功能扩展可直接深化一个方向；探索任务可先做 2–3 个，数量服从用户需求与实际范围。

## 先约定可比较的内容

各方向使用相同任务、关键数据、起始场景与本次承诺的功能。先从同一代表页面或任务起点进入，再体验各自的主要操作。

首页、学习页、复习页是不同页面；Light / Dark 是一个方向的环境适配。它们不单独充当不同概念。增加颜色、字体或排版变体可以是有用的精修，但应称为同一方向的变体。

## 分别构思，再分别实现

每方向依据 [产品主题](product-theme.md) 留下自己的短便笺：产品解释、核心对象、主要动作、材料和模块延伸。差异应在内容如何组织、用户如何理解或操作共同任务上产生可见后果，不按改变维度的数量判定。

有多个 agent 时，可交给它们相同的任务事实和数据，各自发展已分配的概念；没有时也分别从便笺开始。不要把 A 的完成页面复制成 B/C 再寻找变化。可共享数据模型、业务动作、草稿管理、基础输入与导航实现，各方向自行决定画面和交互表达。

独立探索的意义可参照 [NN/g 的并行设计说明](https://www.nngroup.com/articles/parallel-and-iterative-design/)。本文不把其研究设置、测试人数或迭代次数变成生成流程。

## 差异怎样进入同一功能

以“选择看海时间并保存提醒”为例：

| 方向解释 | 用户首先理解什么 | 模块如何协作 |
|---|---|---|
| 潮汐仪表 | 时间变化与海况之间的关系 | 时间输入联动曲线与读数，推荐窗口承接行动，编辑面安排提醒 |
| 海岸图鉴 | 地点之间的关系与各自条件 | 地点分布建立位置感，地点详情与时间轨支持判断，仍能保存提醒 |
| 出海手札 | 今天的时间如何安排 | 日期、时段和边注组织信息，展开窗口查看条件，保存后留在计划中 |

这是已选择任务的一组示例，不是默认三主题套餐。其他产品应产生自己的解释。三者不能通过丢失时间选择、地点切换或提醒功能来显得不同。

## 延伸与比较

主题覆盖本次实际制作的核心模块、相关详情和操作结果。基础导航、返回和输入习惯可以一致；不为区别而隐藏入口或改写保存语义。双模式只在用户要求、现有产品或场景需要时制作，并保持各方向约定一致。

交付每个方向的真实封面、独立体验入口及一句具体区别。封面使用共同初始场景，各原型状态独立；用户可以继续操作、返回总览和重置。不要让不同的内容量、数据或初始状态代替设计差异。

[案例索引](examples/index.md) 用于扩大选择空间。某个案例特别适合一个方向时，也无需让所有方向都以它为骨架。
