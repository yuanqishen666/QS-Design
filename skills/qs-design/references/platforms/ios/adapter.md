# iOS / iPadOS 平台适配器

以漂亮、鲜明且能实际操作的成品为目标。熟悉的导航和输入习惯支撑使用；真实内容、排印、图像、图形与有意义的操作形成产品性格。视觉与行为一起制作。

## 创作方式

- 从用户任务出发：在本次范围内保留已有功能与业务语义，用真实或可信内容做设计。
- 使用用户提供的任何参考或任何已实现内容时，只提取功能、业务逻辑与契约；按 [参考事实边界](../../core/functional-source-boundary.md) 隔离其中的页面结构、布局、样式和交互编排。
- 模块由内容关系决定形态；同一主题允许曲线、列表、编辑面等各有分工。
- 多方向分别构思产品解释，使用同一任务和数据比较。共享数据与适合复用的行为代码，各自形成整页结构。
- 参考库扩展材料与做法，不定义风格全集。借鉴成立原因；示例的品牌、骨架和参数属于该例，允许不用范例或继续搜索。
- Light / Dark 按用户要求、已有产品和使用场景确定；双模式属于同一方向。

## 隔离每次设计

开始前先判断这次是新设计、继续打磨，还是比较已有方向。普通设计请求默认是新设计：理解产品时忽略 `design/qs-design/**`，不把旧原型当作本次需求或视觉依据。只有用户明确说继续、修改、基于某版，或点名具体产物时，才读取对应的一份父版本；比较或融合也只读取用户点名的版本。

同一会话内对当前成品的小调整直接留在当前版本。跨会话继续打磨时，新建子版本并保留父版本，不覆盖来路。若用户明确要继续，但现有信息无法确定是哪一版，只问这一个必要问题。完整规则与目录用法见 [版本与会话隔离](run-isolation.md)。

## 六步制作

### 1. 理解任务与范围

先按 [版本与会话隔离](run-isolation.md) 判定新设计、继续或比较，再使用消息、功能文档、接口、类型、测试和独立品牌资产确定本次功能范围、主要动作与业务结果，准备共享数据。不要从现有页面模板或样式推导新页面。信息够用就开始；只为会改变结果且无法推断的缺口提问。

已有产品读 [功能保留](functional-preservation.md)；确有歧义时读 [上下文路由](context-routing.md)。

### 2. 独立形成三个主题

新设计固定从三个互不查看成稿的概念开始，不因单页、成熟品牌、已有流程或现成实现减少数量。每方向用短便笺写清：产品解释、核心对象、主要动作、信息结构、操控模型、视觉材料和模块延伸。三个方向分别从便笺实现，不能复制一个方向的页面骨架再换色或重排。

需要推导时读 [产品主题](product-theme.md)、[方向系统](direction-system.md) 和共享的 [方向策略](../../core/direction-strategy.md)。只有已选方向后的迭代或机械修改/审计不做三套。

### 3. 让模块形成画面

先确定整页主角和阅读路径，再按“任务与内容 → 关系 → 形态 → 操作反馈 → 画面权重”设计核心模块，用少数稳定视觉角色组合。取得真正需要的素材后，把它放进构图。研究随具体问题发生，已有足够依据就制作。

按缺口选择 [功能单元](function-unit-design.md)、[视觉工艺](visual-craft.md)、[审美系统](aesthetic-system.md) 或共享的 [视觉基因](../../core/visual-genome.md)。找材料读 [来源入口](source-registry.md)，研究奖项读 [奖项与认可](../../sources/awards-and-recognition.md)，找具体解法读 [案例索引](examples/index.md)，需要研究方法读 [参考研究](reference-research.md)。只加载相关条目，奖项只用于发现候选，不直接证明产品质量。

### 4. 制作待评审原型

默认为三个方向分别制作可点击 HTML；独立原型先用 `scripts/ios/design-run.mjs` 分配本次目录，再只在这个目录里写成品。三个原型可共享业务数据和无视觉行为代码，但各自拥有页面结构、组件组合和主题样式。设计阶段不得修改现有 SwiftUI/UIKit 产品源码；需要验证原生能力时使用隔离 sample，并清楚标明与真实工程的差别。把主场景的视觉与真实状态一起实现：明显可点的入口有对应结果，编辑能保存与取消，进入后能返回。只实现本次任务需要的状态；动作即时响应，动画可被新输入接管。

读 [原型交付](prototype-output.md) 和共享的 [内容设计](../../core/content-design.md)。复杂动作读 [交互语法](interaction-grammar.md) 与共享的 [交互基因](../../core/interaction-genome.md)；临时编辑读 [浮层](patterns/transient-surfaces.md)；相关任务再读 [标准模式](patterns/standard-patterns.md)、[叠卡](patterns/stacked-cards.md)。HTML 可以表达结构、状态与运动；原生触觉和系统行为需对应原生实现。

页面缺少动态或任务存在连续操控、容量、阻力、分离、旋转等因果关系时，先读 [具身交互机会扫描](../../core/embodied-opportunity-scan.md)。通过评分后进入 [交互实验模式](../../modes/interaction-lab.md) 做 3–8 秒探针；不强制任一方向套生活物品动画，也不把用户举例写成默认模块。

### 5. 精修并提交评审

逐一看三个原型的实际渲染，修正排印、图标对齐、素材裁切、间距、对比、内容重复和操作节奏；逐一走通同一核心路径。每个方向记录真实入口与从该原型捕获的封面，并用一句话说明产品解释、信息结构、操控模型和视觉材料差异。`directions.json` 与三套产物通过门禁后才能标记为 `review_ready`。同时展示三套后停止，等待用户明确选择或提出修改。

### 6. 按批准版本实现

用户明确批准后运行版本批准命令并验证原型哈希，再读 [SwiftUI 交付](swiftui-delivery.md) 修改现有工程。实现只补足批准设计所需的技术细节；任何改变信息架构、用户可见文案、视觉方向或标志性动效的偏移都先更新原型并重新确认。完成后在真实工程复验核心路径与平台行为。

六步是创作与批准顺序；新设计固定三方向，不要求固定返工轮次。默认展示三套原型与必要说明；用户询问依据时再展开研究。素材所需署名保留在合适位置。来源与复用边界见 [原创性与来源](originality-and-sources.md)，有具体使用摩擦时再读 [社区反馈](community-pain-patterns.md)。
