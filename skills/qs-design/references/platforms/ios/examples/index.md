# 按任务阅读案例

案例帮助打开选择空间。先确定当前功能对象、用户动作和希望形成的体验，再看匹配的案例；不要求先读完所有示例，也不把示例数量作为生成门槛。

## 当前问题对应哪张卡

| 当前问题 | 可读的对照或机制 | 可以带回当前产品的思考 |
|---|---|---|
| 相同任务怎样形成不同主题 | [Things](product-cases.md#case-things) / [Clear](product-cases.md#case-clear)；[Gentler Streak](product-cases.md#case-gentler) / [Waterllama](product-cases.md#case-waterllama) | 信息组织、操作语言、鼓励方式怎样形成区别 |
| 同一内容怎样用于不同功能模块 | [Mela](product-cases.md#case-mela) / [Day One](product-cases.md#case-dayone) | 收藏、编辑、执行和回顾需要不同形态；共享内容关系与主题 |
| 同一领域为什么可以有不同操纵方式 | [Endel](product-cases.md#case-endel) / [djay](product-cases.md#case-djay) | 持续声景与主动混音的任务不同，不能直接当成同一产品的两个方向 |

## 完整分类

- [产品案例](product-cases.md)：25 张，含产品任务、可迁移原则、变化空间、限制和证据。
- [交互案例](interaction-cases.md)：20 张，按原生、Web 与作者案例分组，含实现入口与状态边界。
- [选材配方](material-recipes.md)：10 个本研究建议；不是既有成品、效果保证或固定行业模板。
- [来源路由](../source-registry.md)：需要素材、原始代码、具体社区讨论或数据时从这里查。

可以按案例 ID 或任务词检索相关文件，不需要加载全套。参考可以共享，主题不必接近；当前产品的多个方向应保留同一批承诺功能，不能通过删掉难做的功能制造区别。拿走机制与原则，把内容、构图、材料和交互重新组合。

资料快照为 2026-10-27；实际读取或体验范围以每张卡的证据字段为准。Tidefold 属于本仓库原创演示，外部案例则保持参考卡形式。
