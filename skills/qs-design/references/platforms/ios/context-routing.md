# 上下文路由：什么时候直接做原型，什么时候问

## 默认姿态

先检查已有上下文，再决定是否提问。用户不是产品经理培训对象；不要让他重复提供已经存在于消息、附件、代码、截图或公开产品资料里的信息。

先判断用户是否明确表达“继续上一版、修改某版、基于这个原型”。有明确延续意图才读取旧生成物；普通请求即使功能同名，也按全新设计开始，不询问是否沿用。规则见 [版本与会话隔离](run-isolation.md)。

## 四档判断

### 1. 已知：直接制作隔离原型

满足任一项即可开始：

- 功能属于成熟 iOS 模式：登录、注册、搜索、设置、Tab、菜单、列表到详情、基础表单。
- 用户给了具体内容、字段、页面清单、流程或业务规则。
- 用户给了截图、URL、参考 App、Figma 导出、现有代码或 design system。
- 同一项目已经确定品牌和视觉方向。
- 用户明确说直接做、按最佳判断做或不要再问。

不要为了显得严谨而追问按钮颜色、圆角、设备型号等可由系统或项目上下文决定的细节。“直接做”表示不为低影响问题打断原型制作，不表示可以越过原型批准门禁修改产品源码。

### 2. 可推断：声明假设后执行

当缺失信息不会改变产品本质时，采用稳妥默认值。用一两句话说明关键假设即可，不等待确认即可制作原型；实现仍等待用户批准原型。

例：读书笔记首页可默认围绕“继续阅读、最近笔记、快速记录”组织；普通消费级 App 默认使用熟悉的 iOS 导航与语义字体。

### 3. 低影响歧义：自己选择

配图风格、次要排序、辅助文案、非关键页面顺序等，选择最符合主题与主任务的方案。必要时在交付里列为可调整项，不提前打断。

### 4. 高影响歧义：问最少的问题

只有当答案会改变信息架构、主流程或视觉基调时提问，例如：

- 页面最重要的任务在两种解释中完全不同。
- 面向普通用户还是专业用户会改变密度和术语。
- 产品是交易、医疗、儿童等高信任场景，但关键业务边界不清楚。
- iPhone-only 与 iPad 多窗口会改变核心结构，且无法从项目判断。
- 用户明确要求继续已有设计，但多个旧版本都可能是目标，且没有路径、版本号或清晰的已选版本。

一次优先问一个问题，最多一组 1–3 个。每个问题都应能对应一个明确设计决策。

## 好问题的形式

不要问“你喜欢什么风格”。改问：

- “首页优先帮助用户立即开始一次训练，还是先查看长期进展？这会决定首屏结构。”
- “这些卡片是可快速扫读的清单，还是一次只处理一张的任务队列？这会决定是否使用叠卡。”

问题给出为何重要，但不要把十个选项扔给用户。
