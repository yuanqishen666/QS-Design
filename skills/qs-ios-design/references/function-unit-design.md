# 功能单元：由内容关系决定形态

复合页面需要同时处理多个任务时读取。先定整页主角和阅读路径，再细化模块；模块设计的目的不是增加更多容器。

## 一条推导链

对影响画面的核心模块，在工作上下文中写清：

```text
任务与必要内容 → 用户需要理解的关系 → 表现形态 → 操作与反馈 → 在整页中的权重
```

例如：比较一天中的潮位与适合时段 → 时间与变化 → 连续曲线和时段标记 → 调整同一时间输入，曲线读数与推荐同步更新 → 整页主角。

快速记账则可能是：输入金额与分类 → 数值与归属 → 就近的数字输入及分类选择 → 保存后更新记录、可撤销 → 主任务；无需先放一个趋势仪表盘。

普通按钮、分隔和辅助标签不需要单独填写设计卡。只处理实际存在的功能与状态。

## 从关系寻找可选形式

| 内容关系 | 可考虑的形态 | 自然产生的操作 |
|---|---|---|
| 时间与变化 | 曲线、时间带、日历、连续记录 | 选择或连续取值，关联内容响应 |
| 地点与距离 | 地图、路径、地点分组 | 选择地点，详情保留同一对象 |
| 比较与决策 | 对齐指标、并列候选、重叠图形 | 切换维度、选择比较对象 |
| 队列与处理 | 单项工作面、可扫读队列、分组 | 处理后原位推进，按语义撤销 |
| 归属与组织 | 分组、层级、目标区域 | 放入、移出、展开关系 |
| 输入与创作 | 直接编辑面、邻近工具 | 就地输入，预览与提交 |

这张表提供推理线索，不按行业分配模板。连续值和离散选项可能需要不同输入；地图、叠卡和仪表只有在内容关系支持时才有价值。

## 模块分工

主角模块承担最关键的判断或动作，获得足够尺度和空间。支持模块提供读数、证据、选项或下一步，可以更紧凑、更安静。返回、菜单、编辑和系统输入保留熟悉行为。

模块特色可来自结构、密度、信息关系与反馈，无需每块都有新手势、新材质或装饰动效。同主题的曲线、列表和输入面可以共享字体、颜色角色与对齐关系，仍然各自解决不同问题。

组合时顺着用户的决策顺序安排信息，让主动作靠近其对象。容器用于表达实体或分组，留白用于聚焦与停顿；不要为了统一而把所有模块装进相同卡片。多动作工作台可有多个并行操作，只需使任务关系清楚。

## 研究与实现连起来

需要参考时搜索缺口，例如“连续时间输入如何联动推荐”“长文原位解释”“做饭时如何核对配料”，通过 [来源入口](source-registry.md) 与 [案例索引](examples/index.md) 找局部机制。把观察转化到当前内容，不拼接多个品牌的整页外壳。

模块的视觉与状态一起制作。图形、数字和文字使用同一数据；筛选影响真实列表，选择改变实际对象，保存更新可见结果。整页如何建立层次见 [视觉工艺](visual-craft.md)，复杂输入见 [交互语法](interaction-grammar.md)。
