# 标准 iOS 模式：明确时直接做

这些模式不需要先询问“页面是做什么的”；根据用户内容和项目主题直接设计。品牌表达放在内容、排版、素材和少量关键细节里，不破坏成熟行为。

原生工程使用系统能力；HTML 原型采用语义相同的可实现控件，不宣称具备原生导航手势、触觉或系统权限。页面涉及临时界面时读取 [transient-surfaces.md](transient-surfaces.md)。

## 登录与注册

- 主任务是进入产品，不把品牌展示放在表单效率之上。
- 字段数量由业务决定；没有必要的信息延后收集。
- 键盘类型、自动填充、密码管理和错误位置遵循系统习惯。
- 第三方登录按钮保持提供方要求，避免改造成难以识别的图标。
- 品牌插画或动效只占辅助位置，不阻塞输入。

## 导航

- 3–5 个稳定顶层目的地优先 Tab；层级深入使用 NavigationStack。
- 页面级动作放 toolbar 或内容附近，不塞进全局 Tab Bar。
- 自定义 Tab 动画不能移动点击目标或延迟切换。
- 返回行为、标题层级和手势保持系统预期。

## 菜单与动作

- 次要和低频动作放 Menu / Context Menu；主要动作保持可见。
- 危险操作与普通操作分组，并清楚写出后果。
- 图标含义不明确时使用文字，不让用户猜。
- 不用弹窗确认所有正常操作；可撤销通常比反复确认更轻。
- 临时界面按实际任务定义完成与退出。编辑器区分保存与取消；普通菜单无需补造草稿、确认或拖动。只展示已经接通的行为线索。

## 设置

- 按用户心智和任务分组，不按内部模块分组。
- 标签描述开启后的结果；必要说明放在对应项附近。
- 系统级权限提供直接入口或清晰路径，不伪造系统开关状态。
- 设置页通常不需要 signature interaction。

## 搜索

- 搜索入口的位置取决于它是否为顶层任务；不要因为流行就单独做 Search Tab。
- 根据实际数据与功能提供建议、最近记录、空结果或纠错；没有记录和纠错能力时不画假入口。
- 筛选和排序反映领域语义，避免通用漏斗按钮隐藏关键条件。

## 列表到详情

- 列表负责比较和定位，详情负责理解和操作。
- 同一对象可用图像、标题或轮廓做空间连续性，但不强制复杂 hero transition。
- 高频列表优先可扫读性、稳定操作位置和清楚的列表到详情关系。
