# 审计规则

## 证据格式

```text
状态：finding | clean | not-applicable
位置：文件:行 / 页面 / 交互状态
现象：可复现的实际行为
影响：用户目标、错误、可访问性、性能或平台风险
建议：最小有效修复
复验：怎样确认已经解决
```

## 优先级

- P0：阻断核心任务、数据损坏、严重安全/隐私或完全不可访问。
- P1：常见路径失败、无法返回/取消、关键读屏/键盘失败、明显平台冲突。
- P2：边界状态、性能、内容压力或一致性问题，会影响一部分用户。
- P3：可选精修与偏好；不得冒充硬性缺陷。

## 边界

- 只审查用户指定范围；外部库问题要指出版本与调用证据。
- 不凭截图判断不可见行为；无法验证时写明证据缺口。
- 不把 iOS 规则强加给 Android/Web，也不把 Web 可行性推断到小程序。
- 先报告问题，用户要求修复时才修改实现。
