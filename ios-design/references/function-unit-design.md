# 功能单元设计：先解决局部功能，再组合页面

## 为什么不用整页模板

一个页面通常同时承担多个任务。直接模仿整页会把别人的业务优先级、内容结构和品牌习惯一起复制过来。正确做法是按功能拆解，分别寻找最合适的解法，再统一成一个产品。

## 拆解方法

把页面标成以下单元：

- 主任务：用户打开页面最可能完成什么。
- 核心信息：做决定前必须看到什么。
- 次要信息：按需展开或延后出现什么。
- 操作入口：新增、编辑、筛选、搜索、播放、支付等。
- 状态反馈：加载、完成、失败、空、离线、权限等。
- 导航：页面在整个产品中的位置和返回路径。

为每个重要单元写一张简短设计卡：

```text
功能：快速记录一笔支出
用户目标：单手、数秒内完成
必要信息：金额、分类；备注和账户是次要项
交互：数字输入优先，最近分类直接可选
反馈：保存后在原位确认并更新余额，不弹大型成功页
视觉权重：这是主任务，应比趋势图更突出
性能：不使用持续粒子或整屏转场
```

## 研究粒度

研究“功能”，不研究“整页长什么样”：

- 睡眠趋势 → 研究趋势解释和异常表达。
- 快速记账 → 研究输入效率和撤销。
- Mini Player → 研究持续播放、展开与关闭。
- 票券叠卡 → 研究选中、排序、过期与展开。

每个单元最多选取少数真正相关的原则。不要把多个参考产品的标志性外观拼贴在一起。

## 页面组合

组合时按顺序判断：

1. 主任务是否在第一眼可识别？
2. 信息是否按决策顺序出现？
3. 同级功能是否使用一致的表达？
4. 不同单元是否争夺同一视觉焦点？
5. 是否只有一个主要动作或一个明确的下一步？
6. signature interaction 是否服务核心功能，而不是附着在无关位置？
