# 审美系统：让不同页面属于同一个产品

## 统一的不是模板

同一产品共享的是视觉语法，不是所有页面都使用同一种卡片。保持稳定的可以是：

- 字体角色与数字风格；
- 主色如何出现、状态色如何表达；
- 对齐线、边距和内容密度；
- 圆角与直角的使用逻辑；
- 图像裁切、纹理、图形和图标语言；
- 对象怎样进入、展开、返回和完成。

首页、搜索、详情、学习和设置可以有不同结构，因为它们承担不同任务。只要这些稳定关系仍在，页面就会属于同一个产品。

## 熟悉与独特的分工

- 系统导航、返回、键盘、菜单、选择和编辑行为保持熟悉。
- 内容区域、首屏构图、核心对象、品牌字体、图像、色彩与主交互承担独特性。
- 系统组件不是免设计。要认真决定它在页面里的位置、密度、标题、上下文和出现时机。
- 自定义组件不是越多越好，只在标准组件无法表达产品对象或品牌体验时使用。

## 层级不只靠卡片

优先使用尺度、位置、排版、分组、分隔、背景变化、满幅内容和前后景关系。卡片适合独立对象、可点击实体或需要明显边界的内容，不适合把每段说明都包起来。

嵌套容器要有清楚层级：外层定义环境，内层定义可操作对象；圆角、内边距、描边与阴影应随层级变化，不能每层一样。

## iOS 的品牌表达

- 品牌色优先进入内容、动作、状态和反馈，不必给所有系统 chrome 染色。
- Typography 可以非常有性格：利用字重、宽度、衬线与非衬线对比、数字样式和排版节奏，而不是满屏换自定义字体。
- 自定义 icon 应与内容语言一致；通用动作继续使用容易识别的 SF Symbols 或文字。
- Liquid Glass、透明材质和浮层属于交互层；内容需要时才借用，不把材质本身当主题。
- 主要动作与所控制的内容靠近。全宽按钮不是唯一解，按钮宽度、位置和形状应与周围构图协调。

## Light 与 Dark

每个方向默认同时设计 Light 与 Dark，并共用结构、主角、排版与运动语法。

- Light 关注表面明度、边界、阴影和纸面感。
- Dark 关注层级亮度、局部发光、图片压暗或提亮、分隔和饱和度。
- 不用纯黑加霓虹冒充深色主题，也不把白色表面机械变成深灰卡。
- 主题切换必须覆盖所有主要页面和弹层。

## 页面之间的连续性

当用户从列表、卡片、图片或数据点进入详情，保留一个视觉锚点：对象轮廓、标题、图像、颜色或位置从原处延续。返回时沿同一路径收回。即使没有复杂动画，也要让标题、图像和操作位置形成可理解的前后关系。
