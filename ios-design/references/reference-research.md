# 参考研究：按当前问题取用资料

需要补足内容、视觉、交互或实现知识时读取。研究穿插创作，已有足够信息就制作；不要求核心功能凑齐来源类型或先完成一轮资料收集。

## 从缺口选择入口

先说清当前不确定什么，例如“如何让时间输入同时改变曲线与推荐”“中文长文如何组织章节和边注”“素材能否放进可分发 HTML”。

| 当前缺口 | 优先寻找什么 |
|---|---|
| 系统能力、原生语义、版本支持 | Apple 技术资料、系统示例、相关维护记录 |
| 功能状态、页面连接、真实内容组织 | 可用产品、完整流程、录屏或官方帮助 |
| 构图、字体、图像、材料 | 原作者作品、排印案例、领域资产与素材库 |
| 拖动、展开、浮层、连续反馈的实现 | 对应平台文档、可运行示例、作者代码与讲解 |
| 使用困惑、疲劳、熟练操作 | 具体社区讨论、评论、issue，注意情境与版本 |

用户资产、现有产品与本次任务是判断依据。通过 [来源入口](source-registry.md) 找相应分类，通过 [案例索引](examples/index.md) 找同功能或同内容关系的实例；不需要遍历全库。条目只是入口，使用它支持具体判断时应查看对应原文、素材或代码。

## 带回设计决定

按需要选少量相关材料，理解其任务、输入、状态和取舍，然后转化成当前产品的内容对象、构图角色、交互响应或实现方式。可在工作上下文中简记“观察 → 适用原因 → 本产品怎样使用”，不要求另填来源表。

先看当前问题能否解决；如果参考都围绕同一外观，可看不同表达的案例或继续搜索，也可不采用现有范例。案例的参数和品牌属于原作品，不能代替本次设计决定。

搜索组合使用任务与能力词，例如 `scrub time continuous feedback`、`cooking mode ingredients`、`drag scroll drawer`、`阅读 原位注释`。行业名称用于补充背景，不直接映射模板。

## 按证据能说明的范围使用

图片可说明构图，不能证明交互；产品宣传和帮助文档可说明作者描述的功能，不能声称已经亲手操作；代码与演示证明某种实现，不自动证明适合当前用户。搜索摘要适合发现线索，具体判断回到可读原文。

遇到登录墙、付费、删除或无法提取内容时，使用已公开的有效信息或换来源，不反复卡在受限入口，也不把未查看的录屏写成观察。资料已过时或平台能力有疑问时，再核实相关部分。

社区发言用于发现具体摩擦，不能用点赞数替用户任务做决定。保留相反意见和使用情境，历史 bug 不直接推广到当前版本。需要时读 [社区反馈](community-pain-patterns.md)。

## 取用素材与代码

真正采用某项资源时，核对那一项的使用条件、目标平台与必要依赖。代码可合法复用；素材库许可、运行时许可与社区作品许可分别判断，详见 [原创性与来源](originality-and-sources.md)。无需对未采用的目录做整库授权审计。

默认把工作集中在成品。来源说明按用户问题、引用要求及素材署名需求提供，不让研究过程淹没原型。
