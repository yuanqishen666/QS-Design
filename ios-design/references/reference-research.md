# 参考研究：借原则，不抄页面

## 什么时候研究

标准登录、Tab、菜单、设置等不需要每次重新研究。核心首页、领域功能、品牌关键功能和 signature interaction 在动手前必须实际查看相关实现。当前平台设计语言或 API 可能变化时也必须搜索核实。

## 搜索顺序

1. Apple HIG、Design Resources、WWDC 与 SwiftUI 文档：确认平台语义和当前能力。
2. 真实上线产品：看完整任务流，不只看一张 Dribbble 图。
3. GitHub 与技术演示：理解实现结构、性能与系统版本边界。
4. X、YouTube、小红书、Reddit 等社区：寻找真实喜爱点、困惑、疲劳和失败案例。
5. 用户自己的代码、数据与品牌资产始终高于外部参考。

其他 skill、提示词仓库、模板包和二手清单只能作为发现入口，不能成为引用依据。发现线索后回到原始页面重新查看、核实日期与授权，并用自己的语言记录观察。完整边界见 [originality-and-sources.md](originality-and-sources.md)。

## 以功能为查询单位

搜索：

- “iOS expense quick entry interaction”
- “SwiftUI mini player expand transition”
- “iOS ticket wallet card stack”
- “sleep trend explanation app flow”

不要只搜索：“beautiful finance app UI”。

## 参考卡

每个被采用的参考只记录：

```text
来源与日期：
对应功能：
解决的问题：
值得借的原则：
不借的外观或业务假设：
在本产品中的转化：
授权或使用限制：
```

最多选择少量真正相关的参考。多个来源共同指向一个原则时，提炼原则；不要把每个来源的标志性造型拼在一起。

采用前必须写出“本产品的转化”。如果只是换色、换文案、换圆角或换图标，说明仍在复制外壳，继续从产品对象和使用情境推导。

参考卡、URL、研究截图和来源说明默认是内部工作材料，不进入用户看到的方向板、原型说明或交付文案。只有用户明确要求研究依据、来源、授权或版权信息时才展示；若上层系统要求引用，使用最少必要引用，不让来源解释盖过原型本身。

## 社媒证据的权重

社媒用于发现痛点和语言，不作为规范。公开索引可能不完整，热门帖子也不代表全部用户。将重复出现的抱怨转成待解决问题，例如“动画阻塞输入”“手势不可发现”“玻璃影响阅读”，再结合产品情境作判断。

## 素材与代码

- 下载、复制或引入前检查 license、作者、维护时间、目标系统和依赖成本。
- 参考实现优先重写为项目自己的最小组件，不默认引入整套第三方库。
- 不批量抓取付费或受限素材库，不把社区资产重新分发。
- 真实品牌、图片和数据必须来自用户授权或允许使用的渠道。
- 来源注册表不是完成研究的证据；必须真正打开并查看与当前功能相关的页面、视频、代码或素材。
