# 临时界面：Sheet、Popover、Dialog 与遮罩

临时界面把用户带入一个短任务。它首先是状态与退出路径，其次才是圆角、材质和转场。只实现“打开”和一个关闭按钮，不算完成了这个功能。

## 先选对容器

- **Sheet**：与当前上下文紧密相关的短任务、选择或编辑。
- **非模态 Sheet**：用户需要一边操作面板、一边继续影响后方内容。
- **Popover / Menu**：锚定触发源的少量选项或信息；尺寸随内容，不做半屏表单。
- **Dialog / Alert**：必须中断并确认的风险、错误或重要选择，不承载长内容。
- **全屏编辑**：流程较长、内容密集、需要键盘或沉浸操作时，不勉强塞进 Sheet。

## 先写退出图

在画界面前定义：

```text
如何进入：哪个按钮、卡片或对象触发
如何完成：保存、完成、选择或提交后发生什么
如何取消：关闭、取消、向下拖动、点击遮罩、系统返回
未修改时：各取消路径的结果
已修改时：保存、放弃、保留草稿或阻止退出
重新打开：恢复原值、草稿还是最新保存值
辅助输入：键盘 Escape、VoiceOver escape / dismiss action
```

所有取消入口必须调用同一种状态语义，不能“关闭按钮会还原、点遮罩却保留一半状态”。

## 视觉暗示就是行为承诺

- 出现 grabber，表示可以拖动调整 detent 或向下关闭；原型必须实现，不能只当装饰。
- 出现 dimming scrim，必须定义点按行为。轻量、非破坏性的自定义 Sheet 默认点遮罩取消；若不允许，点击时不应像失效界面一样毫无反馈。
- 背景点击“关闭 Sheet”和允许直接操作背景是两件事。非模态 Sheet 才启用背景内容交互；普通模态 Sheet 仍阻止背景控件响应。
- 出现 Close / Cancel / Done / Save 时，名称与结果一致：Close / Cancel 不保存，Done / Save 提交。
- 不能工作的手势线索和按钮不画出来；原型不能用视觉假功能冒充完整度。

原生 iOS Sheet 默认应支持向下滑动关闭。只有强制完成、数据丢失或不可逆流程才阻止交互式关闭，并在用户尝试退出时解释原因。

## 未保存内容

- 没有修改：关闭、遮罩点击和下拉都直接退出。
- 修改可轻易重做：取消时恢复进入 Sheet 前的值，必要时短暂提示“未保存”。
- 修改成本较高：退出时提供“保存草稿 / 放弃修改 / 继续编辑”。
- 必须完成：可以暂时禁止交互式关闭，但提供明确原因和可达的下一步，不制造陷阱。

不要为了避免做状态管理，就把所有自然退出路径删掉。

## 原型最低行为

只要屏幕上可见，对应行为就要接通：

1. 触发源打开临时界面。
2. Close / Cancel 取消。
3. Save / Done 提交并更新父界面。
4. 遮罩点按按既定策略处理。
5. grabber 对应下拉、detent 或至少一段可见的跟手拖动。
6. 修改后退出走未保存策略。
7. 关闭后重新打开，状态与策略一致。

这是生成前的功能定义，不是额外审计报告。实现后只需实际点过这些可见路径，用户交付里不必附测试表。

## SwiftUI 实现取向

优先使用系统 `.sheet`、`presentationDetents`、`presentationDragIndicator` 和系统 dismiss 行为。需要保护未保存内容时，再按状态使用 `interactiveDismissDisabled` 并提供确认路径。只有原生容器无法表达产品行为时才自定义；自定义时必须自行实现遮罩命中、拖动阈值、可中断动画、安全区和辅助功能。

`presentationBackgroundInteraction` 用于决定 Sheet 出现时能否操作后方内容，不等同于“点遮罩关闭”。不要为了实现遮罩点击而意外让背景按钮被触发。
