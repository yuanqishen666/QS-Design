# 原型与方向稿的用户展示契约

## 只展示用户需要看的内容

默认向用户展示：

- 原型截图或动效预览；
- 可点击原型入口（如果存在）；
- 每个方向一句定位与少量可观察差异；
- 需要用户选择时，一个清楚的选择问题。

默认不展示：搜索过程、参考网站、来源链接、参考卡、内部推导、规范解释、素材候选清单、实现日志。用户明确询问来源、版权、研究过程或技术依据时才展开。

## Light / Dark 是一个方向

- 每个方向必须支持 Light 与 Dark 两套主题。
- 同一方向的 Light + Dark 合计为一个方向，不能分别命名为 A/B 或占用两个候选名额。
- 方向板把同一关键页面的 Light / Dark 成对摆放，并共用一个方向标题。
- 可点击原型提供系统跟随或显式主题切换，切换应覆盖全部主要页面。
- Dark 不是简单反色：重新判断背景层级、表面亮度、分隔、阴影、图片与材质；信息结构、主角和交互保持一致。

如果提供三个方向，结构应是：

```text
方向 A：Light + Dark + signature interaction preview
方向 B：Light + Dark + signature interaction preview
方向 C：Light + Dark + signature interaction preview
```

这是三个方向，不是六个。

## 如何证明交互

当交互是方向差异或卖点时，至少提供一种：

- 可实际点击、拖动或切换的原型；
- 简短 GIF / MP4 / 录屏；
- 一张包含关键阶段的交互序列板。

静态首屏只证明视觉，不证明流畅度、跟手感、空间连续性或反馈质量。

## 如何证明方向不同

每个方向先有不同的一句话产品主张，并至少展示一个属于它的主题证明时刻。三张首屏如果共享同一导航、信息顺序、主按钮和交互模型，只是模块位置、尺寸、颜色或卡片外观不同，应合并成一个方向继续迭代。

方向板不必让三个候选都展示完全相同的页面。可以分别选择最能说明该产品解释的核心时刻，但固定用户给定的必要功能和数据事实，避免为了差异而改写需求。Light / Dark 仍然成对展示，不占额外方向。

## 可见交互必须完整

可点击原型里，只要画面出现按钮、Tab、可点击卡片、遮罩、grabber、开关、保存或取消，它们就应具有与线索一致的行为。核心路径至少覆盖进入、操作、确认、取消和返回；临时界面还要覆盖遮罩、下拉与未保存状态。不能把只有一两个按钮接通的展示板称为完整交互原型。

这不是要求向用户交付测试报告。它要求在生成前把状态和退出路径设计完整，并在交付前实际点过画面上最明显的线索。

## 方向说明要短

每个方向只说明用户能观察到的内容，例如：

- “以可拖动的词卡牌组作为学习主角，查词从当前卡原位展开。”
- “以场景照片和声音为主角，句子随播放进度逐词显现。”
- “把待复习内容组织成一条记忆脉冲，时间临近时才抬升到前景。”

不要写“参考了 Apple Design Awards、某个 App、某条 HIG”。这些属于内部研究，不是用户选择方向所需信息。
