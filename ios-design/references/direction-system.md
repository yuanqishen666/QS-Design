# 方向系统：同一产品合同，不同完整表达

## 方向不是功能拆分

一个方向必须是能够独立成立的完整产品表达，而不是从同一产品里各截一页：

- 首页不是方向 A、学习页不是方向 B、复习页不是方向 C；
- Light 不是一个方向，Dark 也不是另一个方向；
- 同一布局换颜色、圆角、卡片大小或模块顺序仍然只是一个方向的迭代。

每个方向都继承同一份功能合同，包含相同的主要页面、入口、状态与业务语义。差异来自产品如何组织注意力、让用户理解任务、呈现内容和操纵对象。

## 先固定比较基准

先选一个最能代表产品的共同起点，例如首页、核心工作台或同一任务的第一步。所有方向都先展示这个相同场景，使用同一批真实内容和数据，用户才能判断真正的视觉与交互差异。

随后每个方向再展示自己的“主题证明时刻”，例如：

- 一条记忆带怎样召回待复习内容；
- 场景画面怎样展开成一句正在学习的表达；
- 词卡怎样从队列移动到已掌握牌组。

主题证明时刻是额外证据，不能代替共同起点，也不能让其他功能从原型里消失。

## 为每个方向写 Theme DNA

在画页面前内部写清：

1. 产品主张；
2. 视觉主角；
3. 版式骨架；
4. 主要交互；
5. 内容与素材语言；
6. 色彩和材质来源；
7. 字体性格；
8. 动效节奏与标志性交互。

方向至少在视觉主角、版式骨架、主要交互、素材语言、运动语法中真正改变三项。差异要在遮住名称与主题色后仍能看出来。

## 不为了不同而破坏产品

方向探索可以改变“怎样做”，不能改变“有哪些功能”和“业务上发生了什么”。如果一个方向靠隐藏查词、取消复习入口或把多个独立队列合并才能成立，这不是创意，是改需求。

同样，不要为了结构差异而让每个方向只完成一小块。每个可点击方向都要能从共同起点进入主要功能页，并保留返回路径。

## 视觉差异要完整

不要只改首屏顶部。一个方向的概念应穿过：

- 首页大构图；
- 核心内容页；
- 搜索、列表或详情；
- Sheet、菜单和完成态；
- Light / Dark；
- 页面之间的进入与返回。

统一来自同一视觉语法，不是复制同一组件。

## 用户看到什么

每个方向只展示：

- 同一共同起点的 Light / Dark；
- 一句自然、具体的定位；
- 一个能看懂的主题证明时刻；
- 可点击进入完整原型的入口。

不要展示 Theme DNA、来源表、规则说明或设计术语堆砌。
