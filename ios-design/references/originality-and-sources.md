# 原创性与来源独立性

## 不是把别人的方法换个名字

外部资料的作用是提供事实、行为证据、实现边界和用户反馈，不是提供一套可以原封不动搬进来的设计。其他 skill、提示词仓库、模板包、教程合集和竞品拆解可以帮助发现线索，但不能成为最终依据，也不能复制其措辞、目录、流程、代码、素材或示例。

如果从别人的清单里发现一个来源，必须重新打开原始页面，判断它是否真的适用于当前功能，并只记录从原始材料中得到的观察。不能把别人的分类和结论当作已经完成的研究。

## 一项功能的独立证据组合

核心功能或新颖交互尽量从四种不同证据中各取所需，而不是依赖一个设计图库：

1. **平台语义**：Apple HIG、SwiftUI / UIKit 文档、WWDC session 或 Apple sample code，回答系统期望和能力边界。
2. **真实任务流**：App Store 上线产品、实际录屏或可操作产品，回答完整任务是怎样发生的。
3. **实现证据**：原作者代码、维护记录、性能说明或能看清手势与时间的实现视频，回答效果是否可行。
4. **使用反馈**：App Store 评论、Apple Developer Forums、社区讨论、X、YouTube、小红书或 Reddit，回答哪里令人困惑、疲劳或失误。

不是每个普通页面都要凑齐四类。只有核心页面、领域功能和标志性交互需要完整组合；标准按钮、导航和设置继续使用成熟原生模式。

## 从观察到自己的设计

每个真正采用的观察在内部写清四件事：

```text
观察到的事实：原实现具体怎样工作
它解决的摩擦：用户为什么需要它
不能照搬的部分：外观、品牌、业务假设、代码或素材
本产品的转化：由本产品对象、动作和情境推导出的新结构或交互
```

只有最后一项进入设计。若“本产品的转化”只是换颜色、换文案、换圆角或换图标，说明还没有形成自己的方案。

## 原创性的最低表现

- 不看 Logo，仍能从视觉主角和主要动作猜到产品在做什么。
- 至少有一项关键结构或交互来自产品对象本身，而不是来自参考作品的外壳。
- 页面可以解释为什么属于这个产品，而不是只解释为什么好看。
- 来源之间若互相冲突，按用户任务、平台语义和长期可用性重新判断，不用“多数投票”拼接。
- 不使用具体设计师的可识别风格做仿制目标，不把获奖作品或热门 App 做成换皮版。

## 代码、素材与引用

- 优先学习行为与结构，再用项目自己的最小实现重写；除非用户明确接受依赖，否则不直接引入完整第三方组件。
- 复制代码、图像、动效文件、字体或声音前核对许可；不能确认就不分发。
- Apple 设计资源、SF Symbols 和品牌资产分别遵守其使用范围，不能因为公开可访问就当作自由素材。
- 研究记录默认留在内部。用户明确询问来源、授权或研究过程时，只给与最终决策直接相关的原始来源。

## 与其他设计 skill 的边界

本 skill 可以被其他工作流触发，但它的 iOS 决策必须来自本目录的产品主题、功能单元、原生交互、性能和 SwiftUI 路由。不要导入其他设计 skill 的方向门、风格库、lint 规则、固定设备外壳、素材脚本、评审分数或展示模板。它们解决的是别的工作流问题，不是本 skill 的知识来源。
