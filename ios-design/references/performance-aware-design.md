# 性能前置的视觉与交互设计

## 原则

性能是设计材料。不要先提出昂贵效果，再假设工程会优化。每个高交互方案都要在构思阶段回答：它带来的信息或情绪价值是什么；发生频率多高；影响区域多大；是否有更轻的表达；低性能或复杂内容下如何自然降级。

## 默认优先级

1. 系统组件自带行为与反馈。
2. 局部状态变化、位移、缩放、旋转和透明度。
3. shared-element、局部 mask、局部 material。
4. Rive、Lottie、Metal、粒子、实时模糊与复杂 3D，只用于品牌核心或产品本身需要的体验。

## 设计阶段的取舍

- 高频交互越频繁，视觉反馈越轻。
- 动画尽量限定在操作对象附近，不让整页重绘。
- 叠卡只渲染当前卡和少量后层；不可见卡片不保持昂贵效果。
- 大图片按实际显示尺寸准备，避免在运动中实时处理超大资源。
- 避免同时叠加多层 blur、shadow、mask、blend mode 和持续渐变。
- 列表或滚动内容中的每个单元不要各自运行常驻动画。
- 持续动画只用于真实持续状态，例如录音、播放、连接或进度；离屏后停止。
- 交互动画必须响应手势并允许中断；不要用固定延时让用户等待。
- 先用布局、颜色、字体和素材解决层级，再考虑动态效果。

## 复杂效果的准入问题

只有多数答案为“是”时才使用：

- 去掉后，用户会更难理解状态或空间关系吗？
- 它是产品的重要记忆点，而不是常规按钮吗？
- 它不会频繁重复到令人疲劳吗？
- 它可以局部渲染并在离屏时停止吗？
- 它有简单、自然的降级表达吗？

如果效果只让静态录屏更吸引人，但日常使用更慢、更乱或更耗电，拒绝它。
