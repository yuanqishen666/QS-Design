# 交互语法：由输入与状态产生质感

设计拖动、展开、连续取值、对象转场等核心交互时读取。简单点击直接实现相应动作，不必为每个控件写一份动效方案。

## 主交互的六行配方

```text
对象：用户抓住或点击什么。
起点：当前页面、对象和已提交状态。
连续响应：输入变化时，哪些内容与几何跟着变化。
完成：什么动作提交，结果怎样可见。
取消与中断：松手未成立、反向操作或系统取消时，状态落到哪里。
替代入口：不用复杂手势时怎样完成同一操作。
```

写在工作上下文即可。操作的结果先成立，再决定它如何运动。比如拖动时间可以连续更新读数与建议，普通松手保留所选时间，点击明确入口再进详情；不要让每次松手都意外跳页。确需两阶段操作时，使提交意图可见且可退回。

## 按用途安排运动

| 用途 | 处理方式 |
|---|---|
| 即时确认 | 按下即有可辨反馈，动作不用等待动画结束 |
| 直接操纵 | 位置或值连续跟随输入；拖动时不追加追赶手指的动画，放手后再吸附 |
| 状态衔接 | 保留对象身份、来源和返回位置；新输入可接管正在发生的变化 |
| 主题表达 | 在有意义的完成、揭晓或选择中表达性格，重复频率服从任务 |

高频不等于完全静止。拖动、切换与按压仍可有细节，但列表和搜索内容不需要反复等待装饰入场。是否使用蓄力、翻转、粒子或大范围位移，由产品对象和意图决定，不给每条流程强配一个炫技动作。

## 状态是事实来源

领域状态、当前页面、编辑草稿和瞬时交互进度按需要分开。保存提交草稿，取消丢弃草稿；动画完成只负责表现，不决定业务是否成功。使用稳定对象标识，让进入、编辑和返回仍指向同一内容。

简单开合使用明确属性的 CSS transition 或原生状态动画；复杂 spring、共享元素或连续数值再使用可中断控制器。新的输入从当前视觉状态接管，避免全局 `isAnimating` 锁和用一串定时器驱动业务流程。

可以复用许可适合的导航、草稿、拖动和运动代码。本 skill 的 `assets/prototype-core.js` 仅是按需行为辅助，说明见 [原型交付](prototype-output.md)；已有工程沿用自己的框架。

## 浏览器输入

- 普通文本与选择使用原生表单控件，单轴数值优先考虑 `input[type=range]`。
- 自定义拖动使用 Pointer Events，追踪活动 pointer，识别意图后再捕获；处理取消、失去捕获、多指干扰与拖后误 click。
- 只在实际拖动区域设置合适的 `touch-action`。横向操作保留纵向页面滚动，不在整个页面关闭滚动和缩放。
- 输入框、选择器、可编辑文本保留浏览器的聚焦、选择与键盘行为，不被统一拖动处理抢走。
- 提供可点击或键盘可用的同任务入口，保持明确标签与焦点；复杂手势不成为唯一办法。

参考 [Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)。临时面板的拖动与编辑归属见 [浮层](patterns/transient-surfaces.md)。

## 连续性与减少动态效果

同一对象可以用标题、图像、轮廓或位置连接前后场景；不必让全屏一起移动。返回时恢复合理上下文，主要操作位置保持可理解。

在减少动态效果偏好下，保留直接操作、选中态和相同业务结果，减弱大范围位移、视差及装饰。结果不依赖 `animationend` 或延迟才可见；输入仍可立即改变当前状态。

## 原生触觉与声音的边界

SwiftUI / UIKit 可在有意义的选择、阈值、吸附或完成时使用原生触觉，按目标系统能力实现。触觉应强化反馈，不能成为唯一结果提示。

HTML 可表达状态、结构、运动及用户主动开启的声音，不能承诺原生 iOS 触觉或完整系统手势。[W3C Vibration 实现报告](https://w3c.github.io/vibration/reports/implementation.html)记录 WebKit/Safari 未实现该 API；不要用网页调用假称已具备 iPhone 触感。触觉是本次重点时走原生实现。

声音用于内容、场景或有意义反馈，由用户主动开启；无需给每次点击叠加声效。具体库和原作者实践从 [来源入口](source-registry.md) 与 [案例索引](examples/index.md) 按需寻找，效果库服务想法，不代替主题决定。
