# QS iOS Design

以漂亮、鲜明且能实际操作的成品为目标。熟悉的导航和输入习惯支撑使用；真实内容、排印、图像、图形与有意义的操作形成产品性格。视觉与行为一起制作。

## 创作方式

- 从用户任务出发：在本次范围内保留已有功能与业务语义，用真实或可信内容做设计。
- 模块由内容关系决定形态；同一主题允许曲线、列表、编辑面等各有分工。
- 多方向分别构思产品解释，使用同一任务和数据比较。共享数据与适合复用的行为代码，各自形成整页结构。
- 参考库扩展材料与做法，不定义风格全集。借鉴成立原因；示例的品牌、骨架和参数属于该例，允许不用范例或继续搜索。
- Light / Dark 按用户要求、已有产品和使用场景确定；双模式属于同一方向。

## 隔离每次设计

开始前先判断这次是新设计、继续打磨，还是比较已有方向。普通设计请求默认是新设计：理解产品时忽略 `design/qs-ios-design/**`，不把旧原型当作本次需求或视觉依据。只有用户明确说继续、修改、基于某版，或点名具体产物时，才读取对应的一份父版本；比较或融合也只读取用户点名的版本。

同一会话内对当前成品的小调整直接留在当前版本。跨会话继续打磨时，新建子版本并保留父版本，不覆盖来路。若用户明确要继续，但现有信息无法确定是哪一版，只问这一个必要问题。完整规则与目录用法见 [版本与会话隔离](references/run-isolation.md)。

## 五步制作

### 1. 理解任务与范围

先按 [版本与会话隔离](references/run-isolation.md) 判定新设计、继续或比较，再使用消息、代码、附件和现有品牌确定这次要完成的页面、主要动作与核心路径，准备共享数据。信息够用就开始；只为会改变结果且无法推断的缺口提问。

已有产品读 [功能保留](references/functional-preservation.md)；确有歧义时读 [上下文路由](references/context-routing.md)。

### 2. 独立形成主题

先决定方向数量。明确单页或成熟品牌通常深化一个方向；用户要求探索或品牌尚未形成时，可从 2–3 个独立概念开始，按任务调整。每方向用短便笺写清：产品解释、核心对象、主要动作、视觉材料、模块延伸。方向差异应改变内容组织或操纵方式，只换色和排版不构成新主题。

需要推导时读 [产品主题](references/product-theme.md)；多方向读 [方向系统](references/direction-system.md)。

### 3. 让模块形成画面

先确定整页主角和阅读路径，再按“任务与内容 → 关系 → 形态 → 操作反馈 → 画面权重”设计核心模块，用少数稳定视觉角色组合。取得真正需要的素材后，把它放进构图。研究随具体问题发生，已有足够依据就制作。

按缺口选择 [功能单元](references/function-unit-design.md)、[视觉工艺](references/visual-craft.md)、[审美系统](references/aesthetic-system.md)。找材料读 [来源入口](references/source-registry.md)，找具体解法读 [案例索引](references/examples/index.md)，需要研究方法读 [参考研究](references/reference-research.md)。只加载相关条目。

### 4. 直接制作可操作原型

默认制作可点击 HTML；独立原型先用 `scripts/design-run.mjs` 分配本次目录，再只在这个目录里写成品。用户要求 SwiftUI 或接入原生工程时沿用项目结构，不把真实业务代码塞进原型版本目录。把主场景的视觉与真实状态一起实现：明显可点的入口有对应结果，编辑能保存与取消，进入后能返回。只实现本次任务需要的状态；复用合法且适合的行为代码。动作即时响应，动画可被新输入接管。

读所选交付方式：[原型交付](references/prototype-output.md) 或 [SwiftUI](references/swiftui-delivery.md)。复杂动作读 [交互语法](references/interaction-grammar.md)；临时编辑读 [浮层](references/patterns/transient-surfaces.md)；相关任务再读 [标准模式](references/patterns/standard-patterns.md)、[叠卡](references/patterns/stacked-cards.md)、[文案](references/ux-writing.md)。HTML 可以表达结构、状态与运动；原生触觉和系统行为需对应原生实现。

### 5. 在成品上精修并交付

看实际渲染，修正排印、素材裁切、间距、对比和操作节奏；实际走通当前核心路径，遇到问题直接修。独立原型完成后记录真正的入口与封面，并把本次版本设为当前选择。封面从成品捕获，并链接到可体验原型；打开本地预览或提供实际可用的托管入口，多方向各用一句话说明区别。GitHub 文件页、截图和 Xcode Preview 说明本身不等于普通用户已经能点开体验。

五步是创作顺序，不添加阶段审批、打分、审计报告或固定返工轮次。默认展示成品与必要说明；用户询问依据时再展开研究。素材所需署名保留在合适位置。来源与复用边界见 [原创性与来源](references/originality-and-sources.md)，有具体使用摩擦时再读 [社区反馈](references/community-pain-patterns.md)。
